# patches/

这里放**对插件源码的原地改动**（如果做过的话）。

## 为什么现在是空的

`dsh-douyin-browser-local` 是打包产物（压缩过的 JS），没法产出可读、可 review 的 diff。
所以三处修复不是改它的源码，而是在**它的决策层之上加适配层**：

```text
插件（浏览器驱动 + DOM 操作）
  ↑ 不修改
适配层（本仓库 skill/）—— 接管"要不要回 / 回不了怎么办"
```

这样做的两个好处：

1. 插件升级不会冲突。适配层只依赖事件与结果，不依赖内部实现。
2. 改动可测。所有判定都是纯函数，能跑单元测试 —— 改压缩代码做不到这一点。

## 如果你确实改过源码

按这个格式放，命名 `<原文件名>.patch`：

```bash
# 在插件目录里
git diff > ../../../dsh-douyin-skill/patches/content-script.patch
```

并在下面补三行说明：

| 文件 | 改了什么 | 为什么不能在适配层解决 |
|---|---|---|
| （示例）`content/observer.js` | 增加撤回事件派发 | 适配层拿不到 DOM 事件，必须由插件侧上报 |

**注意**：不要把插件的完整源码复制进这个仓库。只放 diff。
