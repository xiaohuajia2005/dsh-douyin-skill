# 风险矩阵与灰度手册

> 一句话前提：本项目驱动抖音网页版，属于平台用户协议明确禁止的自动化行为。
> 下面的措施只能降低概率，**不能消除风险**。看不接受这一条，就不要往下跑。

---

## 一、风险矩阵

| 编号 | 风险 | 级别 | 触发条件 | 应对 |
|---|---|---|---|---|
| R1 | 自动化行为被识别，私信功能被限制 | 🔴 | 节奏规律、停留时间方差小、无鼠标轨迹 | 灰度放量；出现验证码立即停机 72h |
| R2 | 账号被封（永久） | 🔴 | 上述行为持续 + 被举报 | **只用小号**；不与主号同设备/网段/手机号 |
| R3 | 被判站外引流 | 🔴 | 回复里出现微信/QQ/链接/电话 | `dm.never_say` 硬拦；发送前二次校验；命中即丢弃重写 |
| R4 | 评论被判垃圾或折叠 | 🟠 | 短时间多条、重复文案、含联系方式 | 日上限 2 条；模板化；同作品去重 |
| R5 | 同设备关联，主号被连累 | 🔴 | 小号与主号共用设备/浏览器/网络 | 独立浏览器 profile；不同时段；最好不同网络 |
| R6 | 对方收到重复回复 | 🟠 | 发送超时后重发 | 幂等键 + 结果不明不重发（`recall.resend_on_unknown=false`） |
| R7 | 平台改版导致脚本失效 | 🟠 | 页面结构调整 | 状态机 HALTED 而非死循环；失败进队列可见 |
| R8 | 深夜回复打扰用户被举报 | 🟡 | 00:00–08:00 自动回复 | `dm.quiet_hours` 静默时段 |
| R9 | 批量回复陌生人被判定骚扰 | 🟠 | 陌生人回复量过大 | 观察期 + 日上限 8 条 + 字数 20 |
| R10 | 法律与平台规则风险 | 🔴 | 对外提供服务 / 商用 | 仅本地测试，不对外，不商用 |

### 三个最容易被低估的

**R5（设备关联）** 比 R2 更危险。主号被封时你不会立刻意识到是小号带来的，
等发现时申诉期已经过了。**用小号之前先把设备和网络分开。**

**R3（站外引流）** 比"自动化"本身更容易导致功能被封。
平台对导流的判定远比对人机行为的判定成熟 —— 它只需要看文本。
所以 `never_say` 是硬拦，不是提示。

**R7（改版失效）** 的失败方式是静默的：找不到元素 → 发送失败 → 消息消失。
这正是本项目要修的东西。装了适配层之后，失败会变成"排队 + 审计"，
但**它仍然不会自己修好**。

## 二、灰度日程

不要跳步。每个阶段至少跑满天数，且每天看一眼审计日志。

| 阶段 | 天数 | 开放能力 | 回退条件 |
|---|---|---|---|
| ① 只看 | 1–3 | 视频观看 | 出现验证码 / 播放不推进 |
| ② 只回 | 4–7 | 观看 + 私信 | 回复重复 / 发送结果不明 |
| ③ 试评 | 8–14 | 加上评论（`comment.enabled=true`） | 评论被折叠 / 收到违规提示 |
| ④ 放量 | 15+ | 全部 | 任何账号异常，回退一档并停 72h |

配置改法：`config/skill.toml`。**只改这一个文件**，不要在两处写不同的阈值。

### 每天的 60 秒巡检

```text
□ 今天有验证码吗？          有 → 停 72h，回退一档
□ 审计里 BLOCK 突然变多吗？  是 → 可能被人当靶子刷，正常，别手动回
□ 有 REVIEW 堆积没人处理吗？ 是 → 这是你唯一需要人力的地方
□ 有 HALTED 吗？            有 → 看 halt_reason，别急着重启
□ 回复里有联系方式漏出吗？   有 → 立刻改 never_say，然后查为什么拦住
```

最后一条是唯一需要"立刻"处理的。

## 三、出事兜底

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 弹验证码 | 行为被判定为自动化 | 停 72h，回退一档，别当天重试 |
| 私信发不出去 | 私信功能被限制 | 停用私信，只用观看，观察 3 天 |
| 消息发出去对方没收到 | 被判拦截/折叠 | 降频，检查是否含敏感词或重复文案 |
| 评论被折叠 | 内容被判垃圾 | 关评论，改模板，跑 `tools/comment_lint.py` |
| 会话一直 HALTED | 平台限流 / 登录失效 | 看 `halt_reason`；登录失效需重新扫码 |
| 回复内容开始变长变油 | 人设漂移 | 回 `persona/persona_xiaoyu.md` 改字数上限，别加形容词 |

## 四、明确不做的事

这些不是"还没做"，是**决定不做**：

- ❌ 不模拟鼠标轨迹 / 随机化指纹来对抗检测。绕风控是另一条路，本项目不走。
- ❌ 不调用非公开接口 / 逆向签名。
- ❌ 不做批量主动私信（这是骚扰，也是封号最快的方式）。
- ❌ 不做多账号矩阵。单账号的问题都还没解决。
- ❌ 不对外提供任何形式的服务。

---

## 五、合规边界

- 自动化操作社交平台通常违反其用户协议，账号风险自负。
- 批量回复陌生人可能被认定为骚扰。
- 处理他人私信内容涉及个人信息，**审计日志里不存正文原文，只存哈希与判定**（已实现）。
- 本项目仅供技术学习与研究。详见 README 末尾的免责声明。
